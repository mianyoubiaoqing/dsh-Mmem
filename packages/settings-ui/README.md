# dsh-Mmem Settings UI workspace

This private workspace package contributes the standalone dsh-Mmem page to DSH's `settings.plugins.tab` slot. Its built Host and browser entries ship through `@mistymoon/dsh-mmem/settings-ui` in the single public npm bundle. It reads the current Session only through DSH's public Session-list hook, then creates a Session-bound Memory Settings caller. The page never accepts Owner identity, `cwd`, an arbitrary Workspace, or Archive paths.

The current management surface displays the exact Active Memory Space and Binding access, applies content/kind/visibility/status filters through the governed Session-bound search, lists matching governed records and Candidates, shows payload-free Observation/revision lineage, edits or explicitly merges Candidates by creating append-only replacements, supports manual and partial-success batch approval/rejection, and requires an explicit keep-both or supersede choice for blocking duplicate/conflict assessments. It reads the versioned approval policy on demand and lets the Owner explicitly choose `manual` or `scheduled-auto` with an IANA time zone and local review time. It also reads the Owner-bound Memory Space sharing policy, switches among `isolated`, `selective`, and `federated`, creates/removes filtered one-way Grants, and creates/removes explicit non-overlapping Federations. Updates use the exact observed revision. A missing current Session fails closed, and a read-only Binding disables all writes while keeping source and policy reads available.

For a live Session whose DSH Workspace has no Active Space, the same tab exposes first-use setup instead of requiring a hand-edited catalog. It can create a Memory Space and bind an existing Space to the current DSH Workspace as read-only or read-write, optionally selecting the one Default Write Space. The browser sends neither Owner nor cwd. Repeating the flow from another DSH Workspace is how one Space is intentionally shared by multiple Workspaces; creating another Space leaves it isolated until an explicit sharing policy says otherwise.

The Host marker owns no Memory data or RPC behavior. The Settings Host shipped as `@mistymoon/dsh-mmem/settings-host` remains the loopback transport authority, and `MemorySpaceGovernanceResolverV1` remains the only route to an Active Space.

Policy persistence is observed by the bundled cancellable local scheduler. The scheduler only runs after the Owner explicitly saves `scheduled-auto`; the bundled rc.8 Evaluator creates fresh no-tool DSH Agent Sessions, while the governance runner retains all Archive mutation authority and revalidates trusted facts before any low-risk automatic decision.
